# MedTrace: краткий контекст для продолжения

## Цель

MVP внутренней платформы прослеживаемости партий медицинских изделий для одного предприятия. Источник требований — `docs/ТЗ-MedTrace.txt`. Основной процесс проходит от приёмки сырья до отгрузки и отзыва; выпуск продукции требует отдельного решения качества.

## Текущее состояние (2026-10-26)

- Приложение на Next.js 16.4.3 / React 19 / TypeScript. Серверные действия в `src/lib/actions.ts`, схема в `migrations/001_initial.sql` и `002_security.sql`, локальная PGlite либо PostgreSQL по `DATABASE_URL`.
- Реализованы авторизация и восемь ролей, приёмка, контроль и решение качества, спецификации, заказы, резерв, фактический расход, производственные этапы и выпуски, склады, отгрузки, обратная и прямая прослеживаемость, блокировки, отзывы, возвраты, документы, аудит, CSV, QR.
- Разделение входящей партии создаёт две дочерние партии с отдельным контролем, решением и документом. Поиск последствий, блокировка и отзыв проходят по дочерним партиям.
- Демо-набор: 3 поставщика, 5 материалов, 2 изделия и спецификации, 6 входящих партий, 3 заказа, 4 готовые партии, 3 клиента, 3 отгрузки, 1 несоответствие и 1 отзыв. От проблемного сырья есть две связанные готовые партии; четвёртая готовая партия не затронута. Одна готовая партия отгружена двум клиентам, остаток 500.
- Усилены права на серверные данные и вложения, назначение производственного запуска, идемпотентность по содержимому, контроль расхода по спецификации, складские переходы, блокировки и вход. Демо-учётки блокируются в production по умолчанию.
- `npm test` (17 проверок), `npm run lint` и сборка Next.js 16 проверены 2026-10-26. Отдельный тест проверяет закрытие таблиц для ролей Supabase Data API. Ранее HTTP-проверка подтвердила доступ по ролям, загрузку и скачивание документа, защиту ссылки, запрет стороннего Origin и ограничение входа. Browser QA после обновления прошёл на 1440×900 и 390×844: ошибок страницы и горизонтального переполнения нет, граф содержит 5 узлов; снимки в `qa/`.
- Для облачного подключения добавлены загрузка `.env.local` в CLI, ключи Supabase нового формата, обязательная проверка полного набора настроек, миграция `003_supabase_api_lockdown.sql`, начальная настройка организации и администратора, проверка PostgreSQL/Auth/Storage. Бесплатная организация Supabase **MedTrace** и проект **MedTrace Pilot** созданы; URL и ключи сохранены в закрытом `.env.supabase.pending.json`. Прямой IPv6 с этого компьютера недоступен, поэтому подготовлен Session pooler через IPv4. Терминал `npm run db:configure` ожидает скрытого ввода пароля БД пользователем. Реальное облачное соединение пока не проверено.

## Быстрый старт

`npm ci` → скопировать `.env.example` в `.env.local` и задать `SESSION_SECRET` → `npm run db:seed` → `npm run dev`. Демо-вход `admin@medtrace.demo` / `MedTrace2026!`. Подробности и резервное копирование — в `README.md`.

## Открытые ограничения

Supabase Auth/Storage и PostgreSQL пока не проверены реальным соединением. После ввода пароля БД нужны `db:migrate:remote`, `db:bootstrap:remote`, `integrations:check` и HTTP-проверка входа/файлов. Локальная PGlite и файлы подходят для демонстрации; рабочее развёртывание требует приватного хранилища, секретов, backup/restore, HTTPS и аудита безопасности. PDF через печать браузера. Казахский перевод неполный. Редакторы планов контроля и шаблонов процесса отсутствуют; заполненные демо-планы находятся в БД. Нельзя представлять MVP как отраслево валидированную систему.
